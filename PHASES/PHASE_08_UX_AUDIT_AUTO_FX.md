# PHASE 8 — تحسينات الاستخدام والتدقيق والتحديث الآلي لأسعار الصرف

**الحالة:** مطبقة بالحدود الموضحة أدناه؛ يلزم تأكيد دورة التطبيق والاختبارات الكاملة في GitHub Actions وعلى جهاز.

## تحسينات الاستخدام والتحقق
- تُعرض رسائل نجاح وفشل عمليات المخزون والفواتير والتسويات في الواجهة بدل ترك الاستثناءات دون تفسير.
- تهيئة قائمة التنقل مؤجلة (`lazy`) لمنع دورة التهيئة التي سببت مرجع `Screen` فارغًا في تقرير الكراش.
- صفحة تقرير الكراش تحفظ Stack Trace وبعض أحداث التشخيص وتتيح نسخه، مع استضافة صفحة التقرير في عملية مستقلة ومسار استعادة احتياطي.
- يمنع تغيير العملة الأساسية بعد إنشاء الأصناف أو تسجيل معاملات ترحيل لأن ذلك قد يخلط تقييمات تاريخية بعملات مختلفة.
- تمنع واجهات المصروفات والصناديق اختيار عملة غير نشطة لإنشاء معاملة جديدة.
- تُراجع النسخ الاحتياطية للتحقق من العملات، وإجماليات الفواتير، ومعرفات الحركات، وكميات المرتجعات والمطابقة بين الاستردادات وحركات الصندوق.
- سير GitHub واحد باسم `build.yml` يشغّل اختبارات الوحدة/Robolectric ثم بناء APK ورفع الـ Artifact.

## التحديث الآلي لأسعار الصرف
- يستخدم `AutomaticExchangeRateUpdater` مصدر fawazahmed0 Exchange API مع مصدر احتياطي.
- يُحفظ نوع السعر `REFERENCE` فقط مع بيان المصدر وتاريخ البيانات؛ لا تُستبدل أنواع `BUY` و`SELL` اليدوية.
- يقوم `WorkManager` بجدولة تحديث أولي وتحديث يومي يتطلب اتصال شبكة.
- أسعار هذا المصدر إرشادية ولا تمثل بالضرورة أسعار السوق السوداني، لذلك يبقى سعر المعاملة اليدوي مطلوبًا للفواتير.

## الملفات الرئيسية
`AutomaticExchangeRateUpdater.kt`, `RateSyncScheduler.kt`, `ReferenceRateSyncWorker.kt`, `MizanApplication.kt`, `CurrencyScreen.kt`, `CurrencyRepository.kt`, `MizanBackupService.kt`, `.github/workflows/build.yml`.

## حدود التحقق
- لا يضمن معالج Java/Kotlin التقاط جميع حالات native crash أو إيقاف العملية بواسطة النظام.
- لم يتم اختبار جلب API على شبكة حقيقية في هذه المراجعة؛ قد يفشل المصدر أو يحجب عملة معينة، وعندها تُعرض رسالة خطأ ولا تُستبدل أسعار الشراء والبيع.
- لم يتم تشغيل Gradle ولا بناء APK في هذه البيئة تنفيذًا لتعليمات المستخدم.
